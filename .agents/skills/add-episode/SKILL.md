# Skill: add-episode

Добавляет выпуск шоу «Студия Союз» по ссылке на YouTube в приложение как новый **Выпуск** (пакет раундов): разбирает его на игры, извлекает контент, обновляет доки и тесты, разбивает работу на тикеты и выполняет их по порядку. Это тот же пайплайн, что уже прогонялся для выпусков `s1e1`, `s1e2`, `s3e24`.

## Вход

```
add-episode <youtube-url> [--season N] [--number N] [--title "…"]
```

- `youtube-url` — ссылка на выпуск (обязательно).
- `--season` — номер сезона; по умолчанию следующий свободный (`max(сезоны) + 1`).
- `--number` — номер выпуска; по умолчанию 1, либо следующий номер в указанном сезоне.
- `--title` — заголовок; по умолчанию `Сезон N · Выпуск M`.

Один ролик = один Выпуск. Сезон — это просто ярлык-группировка; он не обязан содержать больше одного выпуска.

## Порядок работы

1. **Зафиксировать вход.** Определить `season`, `number`, `title`, создать временный каталог для выгрузки (субтитры/сегменты/кадры) вне git.

2. **Субтитры.** Скачать авто-субтитры (ru) и разобрать VTT в таймлайны:

   ```powershell
   python -m yt_dlp --skip-download --write-auto-subs --sub-langs "ru.*" --sub-format vtt -o "<tmp>\ep.%(ext)s" "<url>"
   ```

3. **Границы игр.** В субтитрах найти фразы «Наш … эксперимент называется <Название>» и «подвести итог … побеждает». Получить для каждой игры название и диапазон таймкодов. Парсер VTT (слияние дублей авто-субтитров) — см. `reference/pipeline.md`.

4. **Сопоставление с форматами.** По `reference/game-map.md` перевести название игры шоу в `id` формата и **сверить id по коду** (`src/experiments/index.js`). Если названия в каталоге нет — остановиться и спросить: создать новый формат, переиспользовать существующий или пропустить.

5. **Контент.** Для каждой игры прочитать субтитры в её диапазоне: цитаты, варианты, тексты. Ответы определять из момента «правильный вариант/ответ» (там играет верная песня/цитата). Если по субтитрам ответ не виден — **кадр** (см. ниже), двухступенчато.

6. **Кадр, когда субтитров не хватает.** Скачать сегмент диапазона (720p), вырезать кадр в момент раскрытия, прочитать ответ:
   - исполняющий агент читает картинку → берёт ответ сам;
   - иначе → показывает путь к кадру и берёт ответ от пользователя.

7. **Медиа.** Для аудио-игр и клипов вырезать нужное:
   - сегменты видео (для кадров) — `-f "bv*[height<=720]/b[height<=720]" --download-sections`;
   - аудио — `-f ba --download-sections`, затем в MP3 в `public/media/audio/` (gitignored).
   Команды — в `reference/pipeline.md`.

8. **Запись в приложение.** Добавить пакет в `src/content/episodes.js` (или новый `src/content/<slug>-rounds.js` для крупных наборов), раунды со структурой формата + поле `hint`. Медиа указывать как `media: { localFile, label }`. Если выбрано «создать формат» — добавить тонкий квиз-формат в `src/experiments/show-games.js` и зарегистрировать в `index.js`; нестандартную механику (не квиз) — остановиться и позвать пользователя.

9. **Доки и тесты.** Обновить таблицу выпуска в `docs/content-extraction.md`, при необходимости `DESIGN.md` (таблица экспериментов) и `GLOSSARY.md`; добавить тест на новый пакет в `test/episodes.test.js`. Прогнать `npm test` и `npm run typecheck`.

10. **Тикеты и выполнение.** Загрузить скилл `to-tickets`, разбить оставшуюся работу на тикеты, затем скилл `implement` — выполнять их по порядку с `code-review`. Мержить автоматически (squash, удаление ветки). В конце проверить в браузере и перезапустить сервер.

## Правила

- **Дословность.** Контент берём из выпуска; ничего не выдумываем. Подсказки (`hint`) — на основе фактов выпуска (исполнители, детали, характер цитаты), без выдуманных ответов.
- **Ответ не определён** → кадр; кадр не прочитан → спросить пользователя. Не помечать ответ «угаданным».
- **Незнакомая игра** → спросить, не создавать формат молча.
- **Локальные MP3 не коммитить** (уже в `.gitignore`); в раундах — `media: { localFile, label }`.
- **Мерж автоматический**, но только после зелёных тестов и `code-review`.
